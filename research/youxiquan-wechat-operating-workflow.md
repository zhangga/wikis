# 有戏圈公众号运营工作流

日期：2026-06-07  
用途：把「有戏圈」后续公众号运营固定到同一套选题、写作、发布、复盘流程里。  
关联报告：[有戏圈公众号运营诊断报告（数据版）](youxiquan-wechat-ops-report-2026-06-06.md)

## 0. 固定口令与模板

以后给出新选题时，默认使用这句口令：

> 按有戏AI圈流程，拆一下这个选题：XXX

触发后，先输出选题拆解，不直接写全文。确认方向后，再进入正式写稿。

默认模板：

| 场景 | 模板 |
|---|---|

## 1. 账号定位

「有戏圈」默认按下面这句话运营：

> **AI Agent、开发者工具与工作流变化的中文判断型账号。**

这个号不追求做泛 AI 新闻，也不做纯工具搬运。每篇文章都要帮读者判断：

1. 这个产品、工具或事件正在抢什么入口？
2. 它改变了哪段真实工作流？
3. 普通人、开发者、产品人或团队现在该怎么用、怎么看、怎么避坑？

## 2. 核心栏目

默认维护四个栏目，后续选题优先归入其中之一。

| 栏目 | 适合内容 | 目标指标 |
|---|---|---|
| Agent 快评 | 新产品发布、热点争议、产品路线变化 | 推荐阅读、分享 |
| 工作流拆解 | Prompt、Skill、个人知识库、AI PPT、团队流程 | 收藏、关注 |
| 工具实测 | 开源工具、GitHub 仓库、产品对比、替代方案 | 搜索、收藏 |
| AI 组织与风险 | 账号风控、权限、合规、大厂 AI 转型、企业 Agent | 分享、专业信任 |

生活方式、读书、亲子内容默认不进入主线；除非它和 AI 工具、家庭 AI 使用边界、教育工作流等主题有明确连接。

## 3. 每周运营节奏

### 周一：选题池整理

从这些来源收集候选：

- X / Hacker News / GitHub Trending / Product Hunt
- OpenAI、Anthropic、Google、Kimi、腾讯、字节等官方博客与发布
- LINUX DO、V2EX、开发者社区、公众号后台搜一搜关键词
- 自己正在使用或踩坑的工具

每个候选只记录 5 项：

```md
## 选题

- 主题：
- 核心产品 / 关键词：
- 归属栏目：
- 为什么现在值得写：
- 读者能带走什么：
```

### 周二到周四：写 1-2 篇主稿

默认每周至少保证：

1. 1 篇 `Agent 快评` 或 `工具实测`
2. 1 篇 `工作流拆解` 或 `AI 组织与风险`

如果遇到强热点，可以加更，但不要为了追热点牺牲判断密度。

### 周五或周末：轻复盘

记录当周文章的：

- 阅读人数
- 推荐来源阅读
- 搜一搜来源阅读
- 分享人数
- 微信收藏人数
- 新增关注 / 取消关注

只做趋势判断，不做伪精确归因。

## 4. 选题评分

开写前先给选题打分，满分 10 分。低于 7 分默认暂缓。

| 维度 | 分值 | 判断问题 |
|---|---:|---|
| 主线相关 | 2 | 是否明确属于 AI Agent、开发者工具或工作流变化 |
| 产品关键词 | 2 | 标题里是否能放入明确产品名 / 工具名 / 场景词 |
| 判断空间 | 2 | 是否能说出“不只是 X，而是 Y”的核心判断 |
| 可带走动作 | 2 | 读者读完是否能立刻试一个动作、清单或框架 |
| 传播资产 | 2 | 是否有一句适合转述的话，或一个适合收藏的结构 |

推荐优先写这类高分选题：

- 多产品路线对比：`Kimi Work / WorkBuddy / Coze`
- 明确工具名 + 使用边界：`Hermes Desktop`、`Codex`、`Claude Code`
- 工具方法与约束系统：AI PPT、个人知识库、Prompt / Harness / Skill
- 组织风险：账号风控、企业 Agent 权限、AI First 工程债

## 5. 标题工作流

每篇至少产出 5 个标题候选，并强制覆盖两类标题：

1. **推荐友好标题**：有判断、冲突、结构承诺。
2. **搜索友好标题**：含产品名、工具名、场景词。

推荐公式：

```md
产品名 + 路线判断
工具名 + 反直觉判断
场景词 + 可带走框架
```

示例：

- `Kimi Work、WorkBuddy、Coze，谁在定义下一代 AI 办公？`
- `Hermes Desktop 来了：AI 助手开始住进你的桌面`
- `Codex 真正想做的，不是 IDE，而是 Agent 时代的 App Store`
- `个人知识库怎么搭？gbrain 和 LLM Wiki 给了两条完全不同的路`

## 6. 单篇文章产出结构

每个公众号主题目录仍按仓库规则创建：

```text
wechat-<topic>/
  article.md
  article-publish.md
  imgs/
```

`article.md` 默认结构：

1. 开头：事件或触发点
2. 判断：这件事真正重要的地方
3. 拆解一：它抢了哪个入口
4. 拆解二：它改变了哪段工作流
5. 拆解三：适合谁，不适合谁
6. 结尾：行动建议 + 关注承诺

`article-publish.md` 默认记录：

```md
## 主标题

## 备选标题

## 骨架类型

## 核心关键词

## 推荐发布组合

## 优化摘要

## 传播资产

- 可被转述的判断：
- 可被带走的动作：

## 复盘标签

- 栏目：
- 目标流量：推荐 / 搜一搜 / 私域 / 收藏
- 预期读者：
```

## 7. 文末转化

由于当前账号主要靠推荐流量放大，文末必须承接新读者。

默认文末加入：

> 如果你也在用 AI 改造工作流，可以关注我。我会持续拆解 Agent、开发者工具和真实使用坑。

如果文章适合引导合集，可以加一句：

> 后面我会继续把 Codex、Claude Code、Hermes、Kimi Work 这类工具放在同一张工作流地图里看。

## 8. 发布后复盘

每 2-4 周更新一次复盘，默认使用公众号后台导出数据，放在 `research/youxiquan-metrics/`。

复盘表至少看：

| 指标 | 用途 |
|---|---|
| 阅读人数 | 判断标题和选题入口能力 |
| 推荐来源阅读 | 判断推荐系统是否吃这个主题 |
| 搜一搜来源阅读 | 判断产品名和关键词是否有效 |
| 分享人数 | 判断观点是否有外发价值 |
| 微信收藏人数 | 判断方法、清单、框架是否有复用价值 |
| 新关注 / 取消关注 | 判断内容方向是否带来长期读者 |

复盘结论只需要回答四个问题：

1. 下个月应该继续强化哪两个栏目？
2. 哪类标题获得推荐，但没有带来关注？
3. 哪些关键词开始有搜一搜流量？
4. 哪些内容应该减少，因为和主线弱相关？

## 9. 当前数据给出的默认策略

基于 2026-05-07 至 2026-06-05 的后台数据：

- 推荐来源阅读人数 1351，约占阅读人数按日合计 1614 的 83.7%。
- 搜一搜来源阅读人数 128，已经是第二大来源。
- 累计关注从 21 到 37，净增 16，取消关注 0。
- 阅读表现靠前的文章集中在 AI 办公路线、AI PPT 约束系统、Codex、Hermes Desktop、Claude HTML、Agent Skill 等主题。

因此默认策略是：

1. **继续写 AI Agent 和开发者工具，不转向泛生活方式。**
2. **标题必须同时照顾推荐和搜索。**
3. **多做产品路线对比、工具方法、工作流拆解。**
4. **每篇文章都要有关注承诺和可收藏结构。**
5. **每月用后台数据校准栏目，而不是凭感觉换方向。**
