# 公众号写作 Playbook

用途：以后每次写公众号内容，默认先走这份流程，再产出 `wechat-<topic>/` 下的正式稿件。

关联研究：
- [公众号爆款文章拆解](/C:/work/github/wikis/research/wechat-quality-study-2026-04-07.md)
- [有戏圈公众号运营诊断报告（数据版）](youxiquan-wechat-ops-report-2026-06-06.md)

## 0. 有戏圈当前运营定位

根据 2026-06-07 数据版运营报告，当前公众号默认不再按泛随笔或泛 AI 资讯号来做，而是按下面这句话统一内容判断：

> **AI Agent、开发者工具与工作流变化的中文判断型账号。**

也就是说，以后写公众号时，默认先问：

1. 这个选题是否和 AI Agent、开发者工具、AI 工作流、AI 组织风险直接相关？
2. 它能不能解释一个产品、工具或事件正在抢什么入口？
3. 它能不能给普通人、开发者、产品人或团队一个可执行判断？

如果只是“某某 AI 新闻发生了”，但讲不清工作流变化、使用边界或行动建议，默认不优先写。

### 0.1 默认内容支柱

以后「有戏圈」公众号选题默认优先落在五类里：

| 内容支柱 | 适合选题 | 默认价值 |
|---|---|---|
| AI Agent 产品路线 | Kimi Work、Hermes Desktop、WorkBuddy、Coze、Dify | 看清产品在抢哪个入口 |
| 开发者工具 / 编程 Agent | Codex、Claude Code、Cursor、OpenClaw、MCP | 看清工程工作流怎么变 |
| AI 工作流方法论 | Prompt、Harness、Skill、个人知识库、AI PPT | 给读者可复制动作 |
| AI 工具实测与开源清单 | GitHub 仓库、工具对比、替代方案 | 形成收藏和搜索价值 |
| AI 组织与风险 | 账号风控、权限、合规、AI First、企业 Agent | 建立判断深度 |

亲子、读书、生活方式内容可以写，但默认不作为「有戏圈」主线。除非用户明确要求，或它能和 AI 工具、家庭 AI 使用边界、教育工作流等主题产生清晰连接。

### 0.2 每篇文章的运营任务

近 30 天数据说明：推荐流量占主导，搜一搜有潜力，私域和社交流量偏弱。

所以每篇文章默认同时承担三个任务：

1. **推荐流量任务**：标题有判断、有冲突、有结构承诺。
2. **搜索流量任务**：标题和前 3 段出现核心产品名 / 工具名 / 场景词。
3. **关注转化任务**：文末给出固定关注承诺，让推荐流量知道为什么关注。

文末关注承诺可使用这句或同义表达：

> 如果你也在用 AI 改造工作流，可以关注我。我会持续拆解 Agent、开发者工具和真实使用坑。

## 1. 先选文章骨架

每次开写前，先明确这篇更接近哪一种，不混着写。

### 1. 热点快评型

适合：
- 新产品发布
- 行业大事件
- 公共议题的第一时间判断

默认结构：
- 事件是什么
- 为什么值得重视
- 我们应该怎么理解

### 2. 现象拆解型

适合：
- 新平台玩法
- 爆红现象
- 某个内容或产品为什么突然火

默认结构：
- 现象是什么
- 为什么会火
- 这说明了什么
- 后面会走向哪里

### 3. 人物故事型

适合：
- 分享嘉宾、作者、创始人的路径
- 非虚构选题
- 用具体人物折射更大的问题

默认结构：
- 先把人物带出来
- 再讲关键转折
- 最后提炼成更大的判断

### 4. 方法复盘型

适合：
- 听完分享后的方法沉淀
- 工作流、创作法、成长路径总结
- 想让读者读完就能行动

默认结构：
- 先给核心结论
- 再拆 3 到 5 个关键方法
- 结尾给行动建议

## 2. 标题生成规则

每次至少先写 5 个标题候选，再选主标题。

标题默认检查 5 件事：

1. 有没有判断，而不是只有主题
2. 有没有代入感，而不是纯概念
3. 有没有冲突、反差或意外
4. 有没有结构承诺，例如“3个判断”“4个动作”“一条路径”
5. 有没有“现在就值得点开”的理由
6. 有没有核心搜索词，例如产品名、工具名、场景词或痛点词
7. 标题是否同时满足“推荐会想点开”和“搜一搜能搜到”

如果标题只是把主题换个说法，通常不够。

### 2.1 有戏圈标题公式

优先使用这三类标题结构：

1. **产品名 + 路线判断**
   - `Kimi Work、WorkBuddy、Coze，谁在定义下一代 AI 办公？`
   - `Hermes Desktop 来了：AI 助手开始住进你的桌面`

2. **工具名 + 反直觉判断**
   - `Codex 真正想做的，不是 IDE，而是 Agent 时代的 App Store`
   - `别再让 AI 一句话做 PPT 了，真正好看的关键是这套约束系统`

3. **场景词 + 可带走框架**
   - `普通团队接入 AI Agent 前，先补这 5 个地基`
   - `个人知识库怎么搭？gbrain 和 LLM Wiki 给了两条完全不同的路`

标题不要只写：

- `AI 办公变了`
- `一个新工具发布了`
- `最近值得关注的 AI 热点`

这类标题可能有话题感，但搜索词和点击理由都不够稳定。

## 3. 开头三段的固定职责

### 第 1 段：把读者带进场景

不要先讲长背景，先讲：

- 今天发生了什么
- 我为什么会想写这篇
- 这件事刺中了什么问题

### 第 2 段：直接下判断

这一段要回答：

- 这件事为什么重要
- 我的核心观点是什么

### 第 3 段：告诉读者读完能带走什么

这一段常见写法：

- 我这篇不打算重复新闻，我更想拆清楚什么
- 我会从 3 个角度讲透这件事
- 如果你也在做 X，这篇最值得看的是什么

## 4. 正文节奏怎么控

公众号可以长，但默认每一节都要完成推进。

建议每个小节都包含：

1. 一个小标题
2. 一句本节判断
3. 一段事实、案例或解释
4. 一句把意义抬高一层的收束

换句话说，不写“散着顺下来”的正文，而写“每节都有结论”的正文。

## 5. 四种最稳的正文推进方式

### 方式 A：判断 -> 证据 -> 推演

适合快评和行业观察。

### 方式 B：现象 -> 机制 -> 影响

适合平台玩法、产品趋势、流量分析。

### 方式 C：故事 -> 转折 -> 提炼

适合人物型和分享改写。

### 方式 D：问题 -> 拆解 -> 动作

适合方法论、复盘、经验沉淀。

## 6. 公众号最需要的两种“传播资产”

每篇文章默认至少准备这两样：

### 1. 一句可被转述的判断

例如：
- 真正重要的不是 X，而是 Y
- 这次变化的关键不在功能，而在门槛被改写了

### 2. 一个可被带走的动作

例如：
- 读完后可以照着做的 3 个动作
- 一张判断清单
- 一个简单框架

没有这两样，文章就容易停留在“读完觉得不错”，而不是“愿意转发/收藏”。

## 7. 结尾默认怎么收

默认不要只说“以上，就是我的一些思考”。

结尾更推荐做三件事之一：

1. 回收全文观点
2. 给读者一个行动建议
3. 把讨论抬到更大的问题上

如果主题适合，也可以顺手留一个具体问题，方便后续做评论区互动。

## 8. 摘要优化规则

`article-publish.md` 里的摘要，默认不要直接复制正文首段。

好摘要通常做到三件事：

1. 交代主题
2. 说清这篇拆了什么
3. 给出读者收益

坏摘要常见问题：

- 太像标题重复
- 太像导语空话
- 只说主题，不说价值

## 9. 排版与配图规则

公众号文章默认不是只交付“纯文字稿”，而是交付更接近发布态的阅读稿。

排版默认做到：

1. 小节之间有呼吸感，长段尽量拆成短段。
2. 关键判断句可以加粗，但不要整段加粗。
3. 需要提醒、总结、动作建议的位置，可以用少量图标或 emoji 做节奏提示。
4. 图标和 emoji 只服务于阅读节奏，不替代标题、观点和论证。
5. 列表、引用、加粗和分隔感优先用于承接“判断、方法、清单、金句”。

图标和 emoji 使用原则：

- 开头导读、关键提醒、行动建议处可以使用。
- 正文每个小节不必都用，避免变成符号堆砌。
- 偏行业分析、人物故事、深度复盘时要更克制；偏方法清单、工具教程、热点速览时可以稍微活泼。
- 同一篇文章里保持风格统一，不混用太多不同类型的符号。

配图默认做到：

1. 除封面外，正文补充 2-4 张配图。
2. 每张图都要对应一个明确用途：概念解释、流程步骤、对照关系、方法框架、金句传播或场景补充。
3. 公众号配图默认采用“手绘版科技风”：手绘线稿、水彩或彩铅质感、轻纸张纹理、温暖留白、克制配色、清晰层级，像中文科技专栏里的手绘概念图 / 手绘框架图。
4. 科技风可以使用节点连线、设备轮廓、简化数据面板、流程箭头、模块框架、轻量 UI 卡片等视觉元素，但不要做成写实硬科技海报、赛博风或深色发光大屏。
5. 如果当前任务背景不适合科技风，例如亲子、读书、生活方式、人物故事等，可自行调整为更贴合主题的温暖手绘信息图或绘本质感插图；判断标准是“是否服务主题表达”，不是机械套用科技元素。
6. 手绘不等于随意草稿：封面要有明确视觉主角和标题空间，正文图要能承接判断、流程、对照、框架或金句。
7. 配图优先放在小节开头后、关键判断后、方法框架前后，不为了凑数量插图。
8. 图片文件放在对应主题目录 `imgs/` 下，按出现顺序编号，例如 `01-cover.png`、`02-framework.png`。
9. 正文只使用相对路径引用图片，例如 `![](imgs/02-framework.png)`。

不推荐：

- 只用氛围图填充版面。
- 一篇文章里突然出现风格差异很大的图片。
- 写实摄影、软 3D、赛博科技感、深色发光背景作为默认公众号配图风格。
- 用太多 emoji 让文章显得像社群公告。
- 图片没有服务任何判断，读者删掉也不影响理解。

## 10. 质量自检

交付前逐项检查：

1. 标题是否已经从至少 5 个候选里挑过。
2. 开头 3 段是否完成“场景、判断、承诺”。
3. 是否已经选定一种主骨架，而不是几种混写。
4. 每个小节是否都有自己的判断句。
5. 文中是否至少有一句可被引用的判断。
6. 文末是否至少给出一个可执行动作或明确落点。
7. 摘要是否经过单独优化，而不是沿用首段。
8. 封面图是否与标题和摘要方向一致。
9. 正文排版是否已经接近发布态，而不是纯草稿。
10. 图标和 emoji 是否克制、统一，并真正帮助读者抓重点。
11. 正文配图是否足够，且每张图都有明确用途。
12. 是否符合「AI Agent / 开发者工具 / 工作流变化」账号定位。
13. 标题和开头是否已经放入核心搜索词。
14. 文末是否有关注承诺、合集入口或下一篇预告，用来承接推荐流量。
15. `article-publish.md` 是否记录了推荐发布组合、传播资产和适合复盘的关键词。

## 11. 一套最稳的默认骨架

如果没有更好的灵感，直接用这套结构：

1. 开头：事件或触发点
2. 判断：这件事真正重要的地方
3. 拆解一：为什么会这样
4. 拆解二：这对谁影响最大
5. 拆解三：以后该怎么做
6. 结尾：回收观点 + 行动建议

这套结构适合大多数“热点分享 / 产品观察 / 创作者方法 / 嘉宾分享改写”主题。

## 12. 发布后数据复盘

公众号发布后，默认每 2-4 周做一次轻量复盘。复盘不只看阅读最高，而是看四张表：

| 表 | 目的 |
|---|---|
| 阅读最高 5 篇 | 判断哪些标题和选题能拉入口 |
| 推荐来源最高 5 篇 | 判断哪些内容最适合平台推荐 |
| 搜一搜最高 5 篇 | 判断哪些产品名 / 关键词能沉淀长期流量 |
| 新增关注对应日期 | 判断哪些内容可能更容易带关注 |

复盘时默认记录这几类结论：

1. 哪类选题只拉阅读，不拉关注。
2. 哪类选题阅读不一定最高，但能带来关注或搜索。
3. 哪些标题公式有效，哪些只是看起来热闹。
4. 下一轮应该强化、减少或暂停的栏目。

注意：如果后台数据只能按日期查看，不能直接证明某个关注来自某篇文章，就只做日期级关联，不做伪精确归因。
